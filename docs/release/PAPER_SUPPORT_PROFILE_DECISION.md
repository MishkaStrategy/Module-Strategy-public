# PAPER Support Profile Decision

**Status:** HQ has selected Linux/VDS as the PAPER deployment target, a separate Darwin environment as mandatory acceptance, and one complete PAPER/research support profile and common lock family. The profile scope includes all 26 distribution providers and the listed functional extras; Signal Bot dependencies are included in the common runtime requirements, while process activation remains optional and configuration-controlled. In the current contract, optional activation does not mean a supported install without those dependencies; such an install would need a separately versioned selection/closure and reconstruction contract. The v3 schema binds the per-provider extra selection, but no populated profile, six required lock identities, candidate-specific resolver evidence, or release has been accepted. This document records the decision alongside source facts and remaining profile decisions. It does not create a manifest, select dependency versions or sources, or claim acceptance.

## Recorded HQ decisions

The owner selected the full protected execution contour: an external admission/controller, one-time isolated executors, a separate publisher, authenticated execution receipts, and distinct Darwin acceptance and backtester capacity. PAPER deployment targets Linux/VDS. Darwin acceptance remains a separate mandatory environment; it does not imply Darwin deployment support. Historical backtesting must use a distinct executor class and must not share the PAPER deployment host or the Darwin acceptance node.

These selections settle the topology, but not its operational identity. The Linux distribution, architecture, libc baseline, systemd version, exact Python patches, immutable executor images, runner-group ownership, controller host, signing-key custody, publisher identity, and evidence-store retention policy remain open. GitHub Actions stay disabled until the external runner-group boundary and publisher are independently configured and verified. No SEARCH, PAPER, soak, deployment, publication, or release execution is authorized by this decision.

## Selected support profile and environment contract

The owner has selected one full PAPER/research support profile and common lock family. Its intended scope includes all 26 distribution providers and the listed functional extras; Signal Bot dependency support is in the family, but activation remains optional and configuration-controlled at runtime. The v3 profile binds one selected extra set for each of the 26 Python providers and requires six typed lock identities (bootstrap, build, and runtime for CPython 3.12 and 3.13); this decision does not populate their contents or evidence. The profile keeps `target_environments` for deployment, locks, reconstruction, and builds, and uses explicit `acceptance_requirements` rows to map each gate/provider pair to its acceptance environment. Acceptance-only environments create no deployment, lock, reconstruction, or build obligations. The schema permits exactly one deployment target and exactly two stable CPython runtime entries, one for minor 3.12 and one for 3.13 ([v3 profile contract](../../schemas/platform-release-manifest-v3.schema.json#L1503), [validator runtime checks](../../scripts/platform_release_manifest.py#L1922)). Choosing a base-only package set, declaring all extras as runtime, or dropping an integrated product capability would narrow or distort the declared product scope; none is treated here as already accepted.

## Source-backed product scope

The current release inventory discovers 26 Python distributions from the root and the `applications/`, `modules/`, `plugins/`, and `research/` package descriptors. The profile inventory names those same 26 providers under the required `python_distributions` role, plus a separate Market Data Console role ([inventory](../../profiles/component-inventory.json#L1), [discovery and count invariant](../../scripts/platform_release_manifest.py#L1388)). The manifest validator requires the Python capability to cover the discovered 26 exactly ([validator](../../scripts/platform_release_manifest.py#L2235)). The 26-package count is source-derived; a final version matrix must be regenerated from the frozen source and descriptor hashes, not copied manually into a second inventory.

The documented mandatory PAPER execution chain is `market data → analytical modules → setup adapter → entry → protection/targets → risk/scaling → router → paper execution → position/exit → trading runner`. Signal Bot is explicitly optional and configuration-controlled; Wave Analysis and Liquidity Sweep are separately owned analytical producers ([release checklist](../hq/history/RELEASE_CHECKLIST_V0_6.md#L26)). The broader full-RC scope also names Backtest, Research Runner, Results Aggregator, Strategy Factory, Strategy Audit, Decision Router, Paper Execution, Trading Runner, Signal Bot, System Acceptance, System Recovery, and Control Plane/UI ([HQ roadmap](../hq/ROADMAP_2026-08-12.md#L30)). The target remains PAPER/research only; live execution, private exchange access, deployment, and publishing are outside the cited roadmap scope.

The currently documented local topology binds the Control Plane to `127.0.0.1:8765` and the existing Market Data API bridge to `127.0.0.1:8000`; owner adapters use explicit loopback URLs or server-side attachments, and remote TLS/reverse-proxy deployment is outside that runbook ([Control UI operations runbook](../control_ui/OPERATIONS_RUNBOOK_V1.md#L47)). HQ previously listed “one reproducible supported single-host PAPER topology” as open work under #400 ([HQ roadmap](../hq/ROADMAP_2026-08-12.md#L172)). The selected target is now Linux/VDS, with Darwin acceptance separate. The Linux distribution, architecture, ABI, service manager, network exposure and recovery envelope remain unselected.

The repository now has a platform-neutral typed lifecycle core reused by the existing Darwin Stage-1 service manager. The systemd adapter remains a static unit renderer/installer; there is no Linux owner-composition entrypoint or claim of Linux support. Wiring it requires a deployment-owned owner/source factory interface plus the exact host, state-path, identity and credential policies recorded below.

The owner selected one complete PAPER/research support profile and common lock family.
